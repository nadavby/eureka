# Stage 4: UI Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Replace the Bootstrap/CSS-file frontend with one consistent, accessible, bilingual (English/Hebrew, RTL) design system. Show off the matching pipeline (live status, reasons, side-by-side photos) and keep the particle logo as the landing hero.

**Architecture:**
- Vite + React 19 + TypeScript **strict**, Tailwind v4 + shadcn/ui (new-york, Radix), TanStack Query for server state, react-i18next for text.
- Feature folders (`src/features/<feature>/{api,hooks,components,pages}`) on top of a small `src/lib` (api client, socket, i18n, query client, formatting).
- The old `src/components/**` and its CSS are deleted as each screen is replaced.

## Design system

**Subject:** a lost-property office. Items are **claim tags**, paper tags with a punched hole, a tag number and a stamp.

| Token | Light | Dark | Use |
|---|---|---|---|
| ink | `#14213D` | `#E8ECF5` | text |
| paper | `#F5F7FA` | `#0D1323` | page background |
| card | `#FFFFFF` | `#151D33` | surfaces |
| manila | `#EBC76A` | `#C9A54C` | claim tags, the one warm accent |
| signal | `#2563EB` | `#5B8DF6` | primary actions, particles, focus |
| lost | `#E4573D` | `#F07A63` | "lost" stamp |
| found | `#1F9D6B` | `#3CC08E` | "found" stamp |

**Type:**
- Display: **Rubik** 600/700, used for headings only.
- Body: **IBM Plex Sans** with **IBM Plex Sans Hebrew**.
- Utility: **IBM Plex Mono** for tag numbers, scores and dates.

All of them cover Latin and Hebrew, which RTL needs.

**Signature:**
- `ClaimTag`: a card with a notched corner, a punched hole and a mono tag number (the last 6 characters of the item id, e.g. `#A41F2C`), plus a LOST/FOUND stamp.
- On the match page, two tags are joined by an SVG string, with the score in mono at the knot.

Everything else stays quiet.

**Motion:**
- The particle hero.
- The string drawing in on the match page.
- The status chip pulsing while matching runs.

All of it is disabled under `prefers-reduced-motion`.

**RTL:** only logical utilities (`ms-/me-/ps-/pe-/start-/end-`). `dir` and `lang` are set on `<html>` from the language. Icons that point in a direction are mirrored with `rtl:-scale-x-100`.

## Routes

| Path | Screen | Auth |
|---|---|---|
| `/` | Landing: particle hero, "I lost something" / "I found something", how it works (a real 3-step sequence), sign in | public; signed-in users go to `/items` |
| `/login`, `/register` | Auth cards with Google sign-in | public |
| `/items` | Browse open items: search, lost/found filter, category, grid of ClaimTags | auth |
| `/items/mine` | My items with the live matching-status chip (analyzing / searching / N matches / failed) | auth |
| `/items/:id` | Item detail and its matches | auth |
| `/report/:type` | 3-step wizard: photo (client downscale + HEIC→JPEG) → details → place & date | auth |
| `/matches/:id` | Two tags tied by a string, score, reasons/conflicts, confirm or reject, open chat | auth |
| `/chats`, `/chats/:matchId` | Conversation list + thread (typing, unread, delivered/read) | auth |
| `/map` | Leaflet map of open items with clustering | auth |
| `/profile`, `/u/:id` | My profile (edit, QR) / public profile | auth / public |
| `*` | Not found | public |

## Tasks (each one ends with lint + typecheck + tests + build, then a commit)

1. **Tooling:**
   - React 19, strict TS, `@/` alias, Tailwind v4 plugin, shadcn init plus the components used, Vitest + Testing Library.
   - Remove Bootstrap, FontAwesome, react-icons, the Google Maps SDK, Headless UI, Heroicons and the Tailwind v3 plugins.
2. **Foundations:**
   - Theme tokens and fonts, the `ThemeProvider` (light/dark/system, saved), i18n (en/he, detector, `dir`), the API client (token refresh with a single-flight queue), the query client, the socket client (auth token, reconnect).
   - Tests: the i18n direction switch, and that the refresh queue retries concurrent 401s once.
3. **App shell:**
   - Top bar (wordmark, nav, report button, notifications bell, language and theme toggles, user menu), mobile bottom nav, `RequireAuth`, error boundary, toasts, not-found.
4. **Landing + auth:** the particle hero (recolored, sized to its container, reduced-motion → static wordmark), login, register (avatar upload), Google.
   - **Checkpoint:** screenshots in both languages and both themes, shown to the user before building the rest.
5. **ClaimTag + browse + my items:** the tag component, the status chip fed by `item_status` socket events, filters, and skeleton/empty/error states.
6. **Report wizard:**
   - Photo step with client-side downscale (canvas, 2000 px, JPEG) and HEIC conversion. The server still re-encodes.
   - Details form (zod), then a Leaflet location picker + date.
   - Submit, which takes the user to `/items/mine` with a live status.
7. **Item detail + match page:** tied tags with the string animation, reasons/conflicts, confirm/reject with an AlertDialog, and the contact card once both users have confirmed.
8. **Chat:** list + thread on the authenticated socket, optimistic send, read receipts, unread badge in the nav.
9. **Map + profiles + notifications:** clustered map, profile edit, QR, public profile, notifications popover (mark read / read all).
10. **Cleanup + docs:**
    - Delete the old components, CSS and hooks.
    - Hebrew strings complete (a test makes sure every `en` key exists in `he`).
    - README screenshots placeholder list, PR.
